# Read-aloud and localisation

The app supports Serbian Cyrillic (`sr-Cyrl`), Croatian (`hr`), and English (`en`), with static male-voice recordings in every language. All voices use `-10%` speed:

| Language | Voice | Service ID |
| --- | --- | --- |
| Serbian | Nicholas | `sr-RS-NicholasNeural` |
| Croatian | Srećko | `hr-HR-SreckoNeural` |
| English (British) | Ryan | `en-GB-RyanNeural` |
 Players switch **Читај наглас** on
once; each newly opened question then reads its prompt and four answers in their
shuffled display order. The current answer is highlighted while it plays. The
preference is stored locally; it defaults to off. Turning it off, answering,
leaving a quiz, or hiding the page stops playback. Reading never selects answers
or delays play. Browser autoplay restrictions may require switching reading off
and on again after a reload; playback failure shows that recovery instruction.

## Stable IDs and translated text

`data/quizzes.json` and `data/{pack}.json` contain language-neutral IDs and image
paths. Keep IDs stable, even when wording changes. They are identifiers, not
English sentences that need replacing. Country codes remain valid identifiers.

`data/locales/sr-Cyrl.json` owns the Serbian text and voice configuration. Keys
include `quiz.animals.prompt` and `answer.animals.dog`. Quiz titles, descriptions,
answer labels, and audio-control copy live here. Menus, feedback, score pages and credits use matching keys in `data/ui/`.

`npm run content:generate` builds the Serbian D1 seed and the public locale
catalogues in `web/locales/`. Each catalogue includes a key-to-audio manifest.
Audio filenames hash the locale, voice, speed, and text, so changed wording gets
a new URL while unchanged clips remain reusable. Identical text within a locale
shares a recording. Generation does not change the existing Serbian database
content or migrate saved games.

Sessions already snapshot prompt and answer text. Playback verifies that a
saved game's displayed text matches the catalogue before using its clips. An
older game whose wording no longer matches remains playable with reading
unavailable for that question, rather than playing different text.

## Generate recordings

Generation uses the Microsoft Edge online TTS service through `edge-tts`;
playback only fetches bundled assets from this site. No speech service, key, or
Python dependency is needed on the server or during play.

```sh
python3 -m venv /tmp/kvisko-audio-venv
/tmp/kvisko-audio-venv/bin/pip install -r scripts/requirements-audio.txt
python3 scripts/generate-feedback-sounds.py
npm run content:generate
/tmp/kvisko-audio-venv/bin/python scripts/generate-audio.py --locale sr-Cyrl
/tmp/kvisko-audio-venv/bin/python scripts/generate-audio.py --locale hr
/tmp/kvisko-audio-venv/bin/python scripts/generate-audio.py --locale en
npm test
```

The generator sends locale text to the service, uses three concurrent requests,
retries transient failures, and writes each recording atomically. Rerunning it
skips files already generated. To regenerate an individual recording, remove
its MP3 first. Commit the generated catalogue and audio alongside source changes.
`content:check` checks catalogue freshness and every referenced audio file.
Old unused recordings can be removed after considering saved-game compatibility.

Human recordings can replace individual MP3s at the manifest's paths without
changing playback code. Use the exact catalogue wording. A full human-recorded
voice can use a new `voice` identifier in the locale source, followed by content
generation and recording all the resulting paths. Keep volume and pacing
consistent across clips.

## Current localisation implementation

The flag picker now offers `sr-Cyrl` (Српски), `hr` (Hrvatski), and `en`
(English), remembered in `kvisko-language` browser storage. Serbian remains the
default. UI text lives separately in `data/ui/`; quiz prompts and all 631 answer
labels have matching keys in the three `data/locales/` catalogues. Both are
validated and generated by `content:generate`; checks reject missing keys,
changed interpolation placeholders, and stale generated files. Serbian UI is
bundled as a fallback if a translated UI file cannot load.

Language changes are a presentation preference, rather than a property of a
saved game. The existing Serbian session snapshots and language-neutral IDs
remain authoritative on the server. The client resolves those IDs to the chosen
catalogue without reshuffling choices, changing scoring, resetting progress, or
clearing a submitted answer. It also translates the correct-answer feedback.
Retired subjects without a current translation keep their saved wording.
Serbian games retain their exact saved text, including older wording.

The picker and translations are shared across the quiz, high-score, and credits
pages. Names, photo authors, filenames, source links and licence identifiers are
proper names/source metadata and remain unchanged. API errors now carry stable
English `code` values alongside the existing Serbian `error` field; the UI maps
the code to its selected language. Scores are stored and ranked independently
of language, while quiz titles and dates are displayed in the chosen language.

Each language has a complete prompt-and-answer audio manifest. Switching
language stops the current reading and uses the new language’s text and
recordings. The read-aloud preference stays enabled across language changes.

To add a future language, set its voice in the source catalogue, regenerate
content, generate its clips, then run the checks. A language without recordings
can use `voice: null`; its read-aloud switch stays unavailable with a translated
notice. Do not reuse another language’s recordings against translated text.

No schema migration is needed for language selection.

## Answer feedback

Every confirmed answer plays an original gentle chime: an ascending bell for a
correct answer and a descending bell for an incorrect answer. Dings play even
when read-aloud is off. `scripts/generate-feedback-sounds.py` creates both WAV
files and a short silent clip used to prepare browser audio in the answer click,
before awaiting the server response. This keeps the same media element available
for feedback on browsers that require a user gesture.

When read-aloud is on, correct answers randomly select one of three localised
praise recordings (`feedback.bravo`, `feedback.correct`, `feedback.right`) after
the ding. Incorrect answers play `feedback.correctAnswer` followed by the
correct answer's existing recording. These phrases use each language's selected
voice and speed. The recorded answer must match the displayed localised label;
retired or changed saved labels never play mismatched speech.

Question reading stops when an answer is selected. Dings, praise, and correct
answer speech share the same sequential player, so they cannot overlap. Players
can continue immediately; the next question cancels unfinished feedback. Leaving
the quiz, hiding the page, or switching language stops audio. A late API response
after one of those actions cannot start stale feedback. Turning reading off also
cancels spoken feedback.
